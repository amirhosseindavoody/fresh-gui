# Workspaces

A daemon can hold several project workspaces. Each workspace has a name, root folder, terminal session, tab list, and expanded explorer folders. The GPUI client shows them in the workspace rail; switching changes the workspace shown without stopping its shells.

## Persistence

The daemon saves workspace names, roots, order, focused workspace, tab titles and order, active tab, editor paths, and expanded explorer folders. It does not save running processes or terminal scrollback. After a daemon restart, terminal tabs return as new shells in their workspace root.

In-buffer search saves only intentionally changed case-sensitive, whole-word, and regex options in the workspace layout. Search queries, replacement text, and selection scope are transient and are never persisted. **Reset options** removes the workspace's saved search override. Search option state follows the active workspace and is independent of the Fresh `.fresh/config.json` settings layer.

**Search in Workspace** always scopes to the active workspace root, independent of the last-selected terminal's directory. It runs on the daemon, follows Fresh-compatible ignore rules unless **Include ignored** is enabled, and streams grouped match previews with cancellation. Select a file or individual matches to replace, or open a result at its line and column. Open dirty buffers and recoverable drafts take precedence over disk and receive revision-checked Fresh edits; unopened files are saved only after daemon-side conflict checks. It searches UTF-8 text files up to 2 MiB, skips paged buffers, and caps each run at 2,000 matches and a 32 MiB replacement review snapshot. Queries and selections are transient.

Quick Finder (`Ctrl+P`) searches files under the active workspace root and can also switch to commands (`>`), open buffers (`@`), or a current-buffer line preview (`:line[:column]`). Finder queries and selections are transient. Confirmed file, buffer, and line jumps share the per-workspace navigation history with definition and symbol destinations; that history is in memory for the client window and is not restored after a client restart.

Settings has a **Workspace** scope that edits Fresh's `<workspace-root>/.fresh/config.json` on the daemon. At Fresh editor startup, project and session layers for the daemon's startup working directory merge above daemon user Fresh settings. The daemon does not resolve a separate Fresh config on each workspace switch, so workspace-specific settings do not update when switching the active workspace. Local client UI settings are stored on the machine running the window; daemon user Fresh settings, terminal defaults, and shortkeys are stored on the daemon host. Fresh editor settings require a daemon restart to apply.

On Linux, the file is `workspaces.json` in `$XDG_STATE_HOME/fresh-gui/` (normally `~/.local/state/fresh-gui/`). On Windows it is under `%LOCALAPPDATA%\fresh-gui\`. `FRESH_GUI_WORKSPACES_FILE` overrides the location and enables persistence in foreground mode.

Editor typing reaches daemon-owned Fresh buffers continuously when range edits are negotiated. The daemon checkpoints accepted edits in durable draft storage scoped to the workspace. Pending edits are flushed before workspace switch, client disconnect, and window close. On workspace activation or reconnect, saved drafts are listed and restored with their path or stable untitled identity and dirty state. For snapshot-sized buffers, missing or externally changed source files retain the draft and display a review warning. Snapshot-sized named files use the `editor.external-changes` capability: the daemon checks file generations every 350 ms using modification time, size, and content hash, including atomic replacements on the daemon host. This makes filesystem reconciliation the same for local and SSH clients. Clean buffers reload automatically. Dirty buffers keep their text and offer **Compare**, **Reload**, and **Keep**; a disk conflict during save requires an explicit **Overwrite disk** choice after review. Compare uses the existing read-only split diff. With an older daemon that does not negotiate external changes, dirty client text remains guarded during snapshot reconciliation, but disk changes are not proactively detected and overwrite conflicts cannot be safely identified.

The client negotiates `editor.draft-recovery`; older daemons cannot guarantee recovery, so dirty-buffer close actions use a native Save / Discard / Cancel prompt. It covers individual tabs, close-others/right/all, pane close, and window close. Cancel leaves the entire bulk selection open. Save waits for every selected buffer to save successfully, including sequential Save As prompts for untitled buffers, before completing the close. Failed saves and cancelled Save As leave every selected tab open. The tab menu also offers **Discard Draft and Close** for explicitly removing a retained draft. The same daemon-side store serves local and SSH clients. A crash can lose edits still in the client’s 75 ms coalescing window or queued behind an unacknowledged request. Deliberate transitions wait for retention; workspace switches wait up to five seconds, and disconnect/restart commands leave the current views open and ask for a retry while drafts are still syncing. Dirty Source Control diff views use the close prompt and block transitions, but their edits are not continuously checkpointed.

Encoding and line-ending conversion run through Fresh on the daemon, including for SSH clients. Snapshot-sized buffers can inspect detected encoding/BOM and line endings, reopen clean files with a selected encoding, save with an encoding, or convert line endings; the latter controls require `editor.file-controls`. Save As and Save All use the existing save protocol. A lossy encode is refused. Paged buffers show detected metadata and preserve it on save; conversion and reopen with a different encoding are unavailable while the buffer remains paged. Encoding and line-ending choices are checkpointed with full-text and paged drafts. Persistent auto-save uses the effective Fresh interval loaded at daemon editor startup and the normal revisioned save pipeline. It applies to open dirty named editors, including format-on-save and Fresh on-save actions; it skips untitled buffers, closed drafts, and Source Control views, pauses while disconnected, and retries after a later interval following a save error. `hot_exit` and `confirm_quit` affect Fresh's own policy only where supported and never disable ADE's Save / Discard / Cancel guards or draft recovery.

LSP rename and code-action workspace edits require the negotiated `lsp.workspace-edits` capability. The GPUI client previews every edit and submits a single-use daemon token; the daemon rechecks open-buffer revisions, Fresh's per-server document versions, closed-file disk generations, and retained draft paths before application. Open buffers use the existing range-edit path, while closed-file text changes use staged daemon writes with rollback on failure. This is best-effort rollback rather than crash-atomic multi-file filesystem replacement; an external writer can race staging or prevent rollback, in which case affected paths are reported. See [workspace edit limits](./FRESH.md#rename-code-actions-and-workspace-edits).

Problems and F8 / Shift+F8 navigation aggregate diagnostics from open editor buffers in the active workspace. The panel supports severity and source filters, related-location links, and code-action quick fixes. The Language Servers panel reports the active editor language's server status and bounded logs, with Start / Stop / Restart controls. These controls require `lsp.controls`; the server lifecycle still follows Fresh configuration, including per-language enabled flags and the global LSP setting. Diagnostic pull for closed files/project scope is not implemented. See [Fresh LSP behavior](./FRESH.md#fresh-editor-integration).

Closing the client window disconnects it and leaves the daemon and its workspaces running. `fresh-gui close` stops the daemon. The last workspace cannot be closed. A workspace with recovery entries cannot be deleted until its drafts are saved or explicitly discarded; reopening the workspace brings retained closed drafts back for review.

## Name and location

Right-click a workspace in the rail to rename it or choose **Change location…**. The daemon saves the new root and authorizes it for file operations. The explorer reloads that folder. Source Control requests git status for the same workspace, so the branch, file list, and root path follow the new location. Diff tabs that were open for the previous location close when the active workspace moves.

## Scope

Definition and symbol jumps maintain a bounded, in-memory back/forward history per workspace in each client window. Switching workspaces cancels pending pickers and file reveals; it retains each workspace's history for later use in that window. History does not change the last-selected terminal directory that drives Explorer and Source Control. It is not part of persisted daemon layout state.

Workspace roots are authorized alongside the daemon root for file operations; they are not separate OS-level sandboxes. Editor buffers are managed by the daemon process. Dock split geometry is persisted with the layout. Fresh currently deduplicates named files across its editor instance, so opening the same file in another workspace is explicitly rejected while the first workspace still holds its buffer; recovery copies remain isolated.

See the [README](../README.md) for normal use and [Architecture](./DESIGN.md) for the client/daemon split.

Large files use the same workspace identity and Save/Discard/Cancel close guards, with a durable edit journal instead of a full-text draft. Reconnect reads the retained page and reconciles it with the local page draft. Daemon restart replays journal transactions only when the source generation matches. If the backing file changed or disappeared, automatic restore fails explicitly and keeps the journal on disk; it cannot reconstruct missing source bytes. Save clears the journal; the recovery budget is 4 MiB of inserted text and edit metadata between saves. See [large-file limits](./FRESH.md#large-files).
