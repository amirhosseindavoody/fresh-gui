# Workspaces

Multiple projects live inside the **one daemon per user**. The GPUI host is a client of that runtime: it lists workspaces, switches which one is on screen, and can disconnect without stopping the others.

This follows [Herdr](https://herdr.dev/docs/concepts/)’s split — a background server owns the processes; a workspace is the project container that owns tabs and terminals — mapped onto fresh-gui’s ADE protocol and GPUI shell. Herdr’s tagline (“the runtime your coding agents live on”) matches the existing singleton-daemon goal. Agent orchestration, pane tiling, and a multi-machine sidebar are follow-ups, not this slice.

## What lives where

| | Daemon (authority) | GPUI client |
|--|--|--|
| Process | One daemon per user (`fresh-gui-daemon` next to the desktop command, or `fresh-gui` on a daemon-only install). `fresh-gui close` stops everything. | `fresh-gui` attaches over `/ws`. Closing the window detaches. |
| Workspace | `id`, display name, canonical root, ADE `session_id`, tab list, focused id | Left rail. Active row is the workspace on screen. |
| Session | One ADE session **per workspace**: PTYs, scrollback, layout blob | The connection is subscribed to **one** session at a time |
| Terminal | PTY child stays running when the subscriber moves or the socket drops | VTE tab bound to that PTY id |
| Editor tab | Path is stored on the workspace. Fresh buffers stay process-global (see follow-ups) | Tab is created only for an `editor_open` this view requested |
| Explorer | Files under the daemon root, plus directories authorized for a workspace root | Re-lists the focused workspace’s root on switch |

```
┌──────────── daemon (one per user) ────────────┐
│  workspace A                workspace B        │
│    session A                  session B        │
│      PTY + scrollback           PTY + …        │
│      tabs: [term, main.rs]      tabs: [term]   │
│                                                │
│  subscriber ──► only the focused session       │
└──────────────────────▲─────────────────────────┘
                       │  workspace_switch
┌──────────────────────┴─────────────────────────┐
│  GPUI: [ A | B ] rail · tabs for the focused   │
└────────────────────────────────────────────────┘
```

Herdr’s “session” is the server namespace. Here that namespace **is** the daemon. A fresh-gui workspace is Herdr’s workspace: one project (or task) with its own tabs. Named Herdr sessions (a second socket and runtime) are not a second daemon; one machine stays one `fresh-gui` process.

## Identity and lifecycle

Ids are UUID strings generated by the daemon.

| Action | Message | Effect |
|--------|---------|--------|
| List | `workspace_list` → `workspace_listed` | Every workspace plus `focused_id` (last successful switch). |
| Create | `workspace_create` → `workspace_created` | New session + record. Does **not** move the subscriber. Empty name → root basename. Empty root → daemon `--root`. An absolute root is `fs_authorize`d so the explorer can list it. |
| Rename | `workspace_rename` → `workspace_renamed` | Display name only. |
| Switch | `workspace_switch` → `workspace_switched` | Detach the previous session (PTYs keep running), attach the target, return its tabs, active index, and live PTYs. Scrollback follows as `pty_data`. |
| Layout | `workspace_layout_set` | Replace that workspace’s tab list and mirror the same JSON onto the session (`version: 5`, `host: gpui`). Any workspace id, not only the attached one. |
| Close | `workspace_close` → `workspace_closed` | Kill that session’s PTYs and drop the record. The last workspace cannot be closed. If it was attached, the connection is left with no session; the host switches to `focused_id`. |

`workspace_switched.tabs` is the tab strip. Live PTYs missing from that list are still returned in `ptys` so a shell opened just before a crash is not discarded. Terminal tabs name a `pty_id`; editor tabs name a `path`.

Switching does not restart the daemon and does not destroy idle workspaces. Disconnect detaches the subscriber the same way a single session already did. The next client lists the same workspaces and switches to `focused_id`.

## Compatibility

Protocol version stays **0.4.0**. `hello` still requires an exact version match, so workspace support is an added capability (`workspace`) and added messages. Old clients never send those messages. The daemon still accepts `session_create` / `session_attach` / `layout_set` for the CLI and older hosts; those sessions are not workspaces. A new host that does not see `workspace` in `hello.capabilities` keeps the previous single-session connect.

PTY open/close on a workspace session updates that workspace’s terminal tabs. Editor membership is only what the host writes with `workspace_layout_set`, so opening a file while workspace A is attached does not append a tab to workspace B.

## GPUI rail

The host paints a workspace rail to the left of the activity bar (168px). **+** asks for a name and an optional absolute root, then creates and switches. The active row can rename or close. Clicking another row saves the current tab list, then switches. Dock panels, terminals, and the explorer root are replaced from `workspace_switched`.

Inside the focused workspace the dock still splits, merges, and reorders, terminal titles are `1`, `2`, `3`, … for that workspace, and the explorer multi-selects. Switching removes those panels without `pty_close` / `editor_close`, so idle PTYs keep running. The saved layout is the center panel order (a flat tab list). Coming back rebuilds one group, so split geometry is not restored.

The host ignores `pty_opened` it did not request and `editor_opened` whose `request_id` it did not send, so a late reply from workspace A cannot insert a tab into B.

## Follow-ups

- Persist workspaces across daemon restart (today they live in memory, same as ADE sessions).
- Per-workspace Fresh buffer namespaces. Buffers are one `EditorWorker` for the process; tab membership is per workspace, but `editor_close` still closes the shared buffer.
- Hard FS jail per workspace root. A custom root is authorized **in addition to** the daemon root.
- Persist dock split geometry across a switch. Splits, merge, and reorder already work in the focused workspace; the saved layout is a flat tab list, so a switch rebuilds one group.
- Agent state rolled up on the workspace row (working / blocked / done).
- SSH multi-machine sidebar. Saved remotes stay a separate target list; they are not workspaces on one daemon.
