# Architecture

`fresh-gui` is a native GPUI desktop client paired with a headless daemon. The desktop command attaches to a local daemon or bootstraps a Linux daemon over SSH. Releases do not include a browser UI.

## Processes

- The **client** renders the workspace rail, explorer, Source Control, editor, and terminal tabs. It connects to the daemon using the ADE WebSocket protocol.
- The **daemon** owns sessions, terminal processes, workspace state, and sandboxed file operations. Linux is the remote SSH target; standalone daemon builds also exist for Windows.
- The daemon embeds Fresh's editor library for opening, editing, and saving buffers. The client displays those buffers in a native GPUI editor view. Above 2 MiB, `editor.paged-reads` replaces full snapshots with metadata and bounded byte-range responses; the client keeps one page in GPUI Kit's Rope and sends global-offset edits through the same revisioned transaction path. Negotiated range edits stream into Fresh transactions; Fresh owns undo/redo and LSP change semantics. The client retains its draft and the authoritative server snapshot when revisions conflict.
- The additive `editor.smart-editing` capability sends explicit selection and smart-edit commands through the daemon's Fresh editor. Ordinary typing and native multi-cursor editing remain in GPUI Kit; Alt-click, column selection, and Add Cursor Above/Below work with coordinated typing. Fresh-backed commands include selection expansion, smart Home/Backspace, newline/tab/dedent, bracket matching, surround, and line operations. Line reordering and unique-line filtering use the existing revisioned range-edit path, so Fresh records them in the same history. Older daemons leave these commands unavailable. GPUI Kit 0.6.6 has no public API for setting all selections, so add-next/all-occurrences and full multi-selection restoration remain limited; see [Fresh editing limits](./FRESH.md#edit-transactions-and-actions).
- Interactive completion, hover, and signature help use the additive `lsp.requests` ADE capability. Requests carry a unique ID, buffer/view identity, base revision, UTF-8 byte offset, feature, and optional trigger/item/server data; the daemon routes each feature through Fresh's `LspManager` and returns per-server results asynchronously. Cancellation, revision checks, and stale-result marking keep responses tied to the requesting view and text revision. Older daemons leave these controls disabled. Paged buffers also disable interactive LSP requests because Fresh/GPUI Kit have no range-backed provider path that avoids loading the full document.
- In-buffer search uses the additive `editor.search` request: the daemon runs a bounded Fresh-compatible preview over the exact client draft, and the GPUI client owns the toolbar, highlights, scope selection, and replacement review. Accepted edits return through the existing revisioned range-edit path as one Fresh undo group. Paged buffers search only the loaded page; see [Fresh search limits](./FRESH.md#in-buffer-search-and-replace).
- The additive `lsp.navigation` capability extends that bridge with definitions, declarations, type definitions, implementations, references, and document/workspace symbols. GPUI Kit's Command widget presents and filters destinations; workspace symbol queries are debounced and superseded requests cancelled. LSP URI/UTF-16 destinations are sent to the authenticated daemon's existing editor opener and converted to absolute byte offsets before reveal. Client history retains origin and destination view identities per workspace, allowing back/forward across panes without changing the terminal-driven Explorer or Source Control directory.
- The additive `lsp.workspace-edits` capability exposes Fresh-routed rename and merged code actions. F2 uses the first eligible rename server and retains that server for its response; Ctrl+. merges code actions with server attribution for resolve and `workspace/executeCommand`. The GUI previews edits before applying them. Daemon-side tokens are single-use and checked against captured open-buffer revisions, Fresh per-server document versions, and closed-file disk generations. Open text edits use #141 range transactions; closed files use staged daemon filesystem changes, with rollback on failures. The daemon limits a transaction to 64 files and 8 MiB, and closed text files to regular UTF-8 files no larger than 2 MiB. Resource create/rename/delete operations are restricted to closed regular files and reject overwrites, directories, symlinks, open buffers, and recovery drafts.
- The additive `lsp.controls` capability gates selection formatting and server lifecycle operations. Fresh remains the formatting authority: a selection prefers supported LSP range formatting; otherwise the configured external formatter runs on the document, with document LSP formatting used only if no external formatter is configured. Format results return over the existing revisioned edit path; format-on-save runs configured external formatters and Fresh on-save actions on full buffers, skipping paged buffers. The Problems panel aggregates diagnostics from open workspace buffers and routes quick fixes through code actions; status and Start/Stop/Restart inspect the active editor's language through Fresh's LSP manager. Older daemons do not receive these new operations.
- **Quick Finder** uses the additive `project.file-finder` capability for recursive workspace file search. The daemon reuses Fresh's public `FuzzyMatcher` and the existing ignore-aware workspace walker, cancels superseded scans, and returns the best 200 paths. The native client also reuses Fresh's fuzzy matcher source for command and open-buffer ranking; it does not link the Fresh editor. `Ctrl+P` routes files, `>` commands, `@` open buffers, and `:line[:column]` preview through one finder. Exact paths can open without waiting for enumeration. Confirmed file, buffer, and line jumps use the per-workspace client navigation history described above; the existing file/directory explorer remains separate.

- **Search in Workspace** uses the additive `project.search.v1` capability. The daemon walks the explicit active workspace root with Fresh-compatible matching and ignore rules, streams bounded file groups, and supports cancellation. The GPUI panel owns criteria and result selection. Dirty open buffers and recoverable drafts use revision-checked Fresh edits; unopened files use daemon-side conflict-checked saves. This scope does not follow the last-selected terminal directory. See [project search limits](./FRESH.md#project-search-and-replace).

A local `fresh-gui` command attaches to or starts the daemon and opens the window. `fresh-gui user@host` uses the system OpenSSH client to install/start a Linux daemon when needed and opens a tunneled connection. Closing the client window disconnects it; `fresh-gui close` stops the local daemon.

Dirty editor buffers are checkpointed by the daemon into durable recovery storage partitioned by workspace identity. The daemon remains the authority for both local and SSH sessions; the client negotiates `editor.draft-recovery` and can list, restore, or discard drafts. A restore keeps the buffer dirty and flags a named draft when its source file is missing or differs from the saved base. Recovery stores editor text only: terminal tabs reopen as new shells after restart, and running processes are not persisted. The accepted edit is checkpointed after it reaches Fresh; because the client coalesces keystrokes for 75 ms, a crash before that edit is delivered and acknowledged can still lose the newest keystrokes.

Settings follow the same authority boundary. GPUI presentation settings are stored on the machine running the client in `fresh-gui/config.json` and apply to that client, including when it connects over SSH. Fresh editor config, terminal shell defaults, and native shortkeys are stored by the daemon in its user `config.json`; Fresh settings are validated and applied using Fresh's typed `PartialConfig` merge behavior. At editor startup, Fresh session and project config layers for the daemon's startup directory take precedence over daemon user settings. Workspace Fresh settings are stored under that workspace's `.fresh/config.json`, but switching the active workspace does not reload the Fresh config. The native settings editor patches JSONC paths so comments and unrelated or unknown keys are retained. Its typed Fresh controls cover a subset of Fresh configuration; Edit JSON remains available for the complete file. Fresh engine settings generally take effect after a daemon restart. Daemon `editor.line_wrap` maps to the live native wrapping preference; explicit local client presentation overrides take precedence. Native shortkeys reload live.

Normal snapshot-sized named editor buffers also reconcile disk changes through the negotiated `editor.external-changes` capability. The daemon checks file generations every 350 ms using modification time, size, and a content hash, so local and SSH sessions use the daemon host's filesystem view. A clean buffer reloads automatically. A dirty buffer retains its draft and shows Compare, Reload, and Keep actions; a save conflict requires a conscious **Overwrite disk** action. Older daemons do not send external-change notices, but the client still guards dirty drafts from being replaced by a snapshot.

Large-file recovery stores a bounded edit journal in the existing workspace draft store, rather than full source text. Restore replays Fresh transactions only against the recorded source generation. Missing or changed sources retain the journal but require manual review; lazy pieces still reference that source, so reads, edits, and saves are blocked after a detected disk change. Large-file generation checks use size, modification time, and Unix file identity rather than hashing the entire source every poll. A same-metadata in-place write can escape detection. See [FRESH.md](./FRESH.md#large-files) for the current limits.

## Client chrome

The GPUI window follows the daemon's theme setting (`system`, `light`, or `dark`). On a light theme the client darkens borders and split handles so they stay visible on a bright background. The split git diff draws a center rule with that same border color.

Source Control lists changed files in a tree grouped by directory under the git root. Clicking a file opens its diff; directory rows expand and collapse. Stage and Unstage stay on each file. Revert asks the daemon to restore a tracked path to `HEAD` in the index and worktree, or to remove an untracked file. Git commands run on the daemon, and paths stay relative to the repository.

The title bar shows the SSH destination for remote sessions, or a short local/direct host label. The status bar shows connection state and the active workspace; protocol capability names remain internal feature gates. Explorer **Copy Path** puts the daemon's absolute path on the client's text clipboard, including when a Windows client is connected to a Linux daemon. Terminal copy and paste use that same clipboard. Tab in a focused terminal is delivered to the PTY; the window's Tab focus cycle does not take it. **File → New Tab** opens a shell and **File → New File** opens an unsaved buffer. **File → Save** and Ctrl+S write the active buffer; an unsaved buffer asks for a path and is created there. The tab-strip **+** offers New Tab and New File. Ctrl+P opens a file from a typed path, using the explorer cache as suggestions. Ctrl+click uses Fresh `path_link::detect_link_at` on the terminal or editor line and opens the file. Ctrl+Shift+P is the command panel, including save, a new terminal, a side-by-side terminal split, and format document (Fresh `format_buffer`).

`Ctrl+=` / `Ctrl+-` / `Ctrl+0` zoom editor and terminal text. `Ctrl+Shift+=` / `Ctrl+Shift+-` / `Ctrl+Shift+0` zoom rem-based UI text; panel text follows both scales. Those chords are default shortkeys in the daemon config. Fixed pixel chrome, including the sidebar width and dock tab strip, does not scale.

Windows embeds `assets/fresh-gui.ico` as icon resource 1. Linux sets the X11 window icon from `assets/fresh-gui.png` and writes a user desktop entry so a Wayland dock can resolve the `fresh-gui` app id.

## Source layout

- `crates/fresh-gui`: daemon, ADE handlers, sessions, PTY, filesystem, and embedded Fresh editor.
- `crates/fresh-gui-app`: native GPUI client.
- `crates/fresh-gui-client` and `crates/fresh-gui-protocol`: client transport and shared protocol types.
- `vendor/fresh`: pinned Fresh submodule used by the daemon.

For Fresh embedding details, see [FRESH.md](./FRESH.md). For workspace persistence, see [WORKSPACES.md](./WORKSPACES.md). Access and token behavior is in [SECURITY.md](./SECURITY.md).
